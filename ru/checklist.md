# Чеклист преподавателя для проверки лабораторной работы

Практический чеклист для быстрой проверки сдаваемой лабораторной работы.
Подробное обоснование каждого пункта — в `common_requirements.md`,
`grade.md` и файле конкретной лабораторной работы (`lab1.md`–`lab4.md`).

## 1. Репозиторий и процесс

- [ ] Работа загружена в **один** git-репозиторий на GitHub, доступный
      преподавателю (не отдельные репозитории на каждую лабораторную).
- [ ] Внутри репозитория есть папки верхнего уровня `lab1`, `lab2`,
      `lab3`, `lab4` — по одной на каждую лабораторную работу.
- [ ] В репозитории нет файлов, не относящихся к исходному коду (артефакты
      сборки, файлы IDE, временные файлы) — есть `.gitignore`.
- [ ] Изменения велись в отдельных feature-ветках, в `main` попали только
      через Pull Request, одобренный преподавателем.
- [ ] Сообщения коммитов содержательны (не `commit 1`, `fix`, `wip`, `asdf`
      и подобные) и отражают, что и зачем сделано.

## 2. Тестирование и сборка

- [ ] Есть unit-тесты, покрытие — **более 90%**.
- [ ] Тесты запускаются из консоли, без привязки к конкретной IDE.
- [ ] Проект собирается из консоли, без использования IDE.
- [ ] Настроен CI/CD-пайплайн на GitHub, который автоматически:
  - [ ] запускает тесты и проверяет покрытие кода;
  - [ ] проверяет качество кода (статический анализ / линтер);
  - [ ] собирает артефакт сборки и публикует его в Releases.
- [ ] Артефакт из Releases можно скачать и запустить независимо от среды
      разработки.

## 3. CLI-интерфейс

- [ ] Есть консольный интерфейс (CLI/меню), демонстрирующий содержательную
      функциональность предметной области (не только запуск тестов) —
      например, добавление/удаление сотрудника, отправка посылки,
      формирование отчёта и т. п.
- [ ] CLI отделён от реализации предметной области.

## 4. Качество кода (частые ошибки)

- [ ] Нет магических чисел и захардкоженных значений (вынесены в константы
      или конфиг).
- [ ] Нет переусложнённых конструкций и лишних абстракций.
- [ ] Вложенность циклов/`if-else` не превышает 3 уровней в одном методе.
- [ ] Методы/функции не длиннее ~20 строк.
- [ ] Строки кода не длиннее ~150 символов.
- [ ] Имена переменных, функций и классов информативны (нет `temp`, `k`,
      `p`, `buffer`, `help` и т. п.).
- [ ] Стиль именования и форматирования единообразен по всему проекту.
- [ ] Нет закомментированного и мёртвого кода, нет `TODO` в финальной
      версии.
- [ ] Нет длинных цепочек вызовов без промежуточных переменных.

## 5. Требования конкретной лабораторной работы

### Лаба №1 (основы ООП: класс)

- [ ] Выбранный вариант задания реализован полностью.
- [ ] Сгенерирована документация штатным генератором для языка (Doxygen /
      Javadoc / XML-документация+DocFX / Sphinx-pdoc).
- [ ] Есть консольная программа с меню для проверки класса.
- [ ] Класс инкапсулирован, консольный UI отделён от реализации класса.
- [ ] Реализованы (где уместно): конструктор копирования и присваивание
      копированием, корректное освобождение ресурсов, сравнение на
      равенство, чтение объекта из текста/потока и запись в текст/поток.
- [ ] Класс и использующий его UI взаимно независимы; объявление отделено
      от реализации средствами языка.
- [ ] Если язык не C++ — специфичные для C++ конструкции (перегрузка
      операторов, `.h`/`.cpp`) корректно перенесены на средства выбранного
      языка (см. таблицу соответствий в `lab1.md`).

### Лаба №2 и №3 (крупный ООП-проект, две разные предметные области)

- [ ] Домены лаб №2 и №3 действительно разные.
- [ ] Не менее **50 классов**.
- [ ] Не менее **150 полей** суммарно.
- [ ] Не менее **100 уникальных содержательных поведений** (не
      геттеры/сеттеры).
- [ ] Не менее **30 ассоциаций** между классами.
- [ ] Не менее **12 собственных классов исключений**.
- [ ] В репозитории есть README, описывающий классы, поля, методы,
      ассоциации и исключения.

### Лаба №4 (обобщённое программирование)

- [ ] Выполнены **обе** обязательные части — сортировка и граф (не одна на
      выбор).
- [ ] Обобщённая функция сортировки работает и с массивами, и со
      стандартной динамической коллекцией языка, для встроенных и
      пользовательских типов; есть демонстрационный пользовательский класс.
- [ ] Реализован граф в соответствии с вариантом (тип представления:
      матрица смежности/инцидентности, список смежности, упорядоченные
      списки рёбер, ортогональный список смежности, структура Вирта и
      т. д.).
- [ ] Контейнер имеет параметр обобщённого типа и не раскрывает внутреннее
      представление наружу.
- [ ] Реализованы: конструктор по умолчанию, конструктор
      копирования/глубокое копирование, проверка на пустоту, очистка,
      присваивание копированием, операции сравнения, доступ/добавление/
      удаление элементов, двунаправленные итераторы (вершины, рёбра,
      инцидентные рёбра, смежные вершины) с обратными и константными
      модификациями, удаление по итератору, текстовое представление через
      итераторы, выброс исключений при ошибках.
- [ ] Студент на защите свободно работает с обобщёнными типами и стандартной
      библиотекой контейнеров выбранного языка.

## 6. Дополнительное задание (если назначено)

- [ ] Рукописный (на бумаге) разбор алгоритма/структуры сдан вместе с
      защитой.
- [ ] Разбор включает: пошаговую трассировку на числовом примере, оценку
      временной и пространственной сложности (Big O) с обоснованием, а для
      структур данных — инварианты и их сохранение при модификациях.

## 7. Защита

- [ ] Устная защита теории: отвечено на **5 вопросов** из `questions.md`.
- [ ] Письменная защита теории: отвечено на **10 вопросов** из
      `questions.md`.
- [ ] Код: выбраны **3 случайных места**, студент полностью объяснил, что
      происходит и почему написано именно так (при неудаче — рукописный
      разбор места и повтор защиты с новыми местами, до полного успеха).

## 8. Итоговая мини-лекция по теории (сдаётся один раз, по итогам всех лаб)

- [ ] Даны ответы на **все** вопросы из `questions.md`.
- [ ] Суммарная длительность записи — **больше 40 минут**.
- [ ] Если видео короче 40 минут — часть ответов раскрыта поверхностно,
      нужно дополнить и переснять.

## 9. Академическая честность

- [ ] Работа выполнена самостоятельно, пройдена проверка на плагиат.
- [ ] Совпадение с чужими работами не превышает допустимого уровня (~30%
      типовых конструкций); совпадение свыше **50%** — основание для
      назначения дополнительной лабораторной работы (см. раздел 6 выше).

## 10. Итог

- [ ] Определено количество сданных лабораторных работ и срок сдачи —
      сверить с таблицей допуска и оценки в `grade.md`.
