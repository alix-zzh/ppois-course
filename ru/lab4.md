# Лабораторная работа №4. Обобщённое программирование: сортировка и контейнеры

Задание исторически сформулировано в терминах C++ (шаблоны, STL). При
выполнении на другом разрешённом языке (см. `common_requirements.md`)
«шаблон» следует читать как «обобщённый тип/функция» в терминологии этого
языка: `template` — в C++, generics — в Java и C#, обычные функции и классы
(с опциональными аннотациями типов и duck typing) — в Python.

Лабораторная работа состоит из **двух обязательных частей** — «Задание 1»
и «Задание 2» ниже нужно выполнить оба, это не альтернативные варианты на
выбор.

## Задание 1. Сортировка

В соответствии с вариантом реализовать обобщённую функцию (или несколько
функций) сортировки. Функция должна уметь сортировать как массивы, так и
стандартные динамические коллекции языка (`std::vector` — в C++, `List<T>` —
в Java и C#, `list` — в Python) для элементов любого типа: как встроенных,
так и пользовательских. Для демонстрации сортировки пользовательских
объектов нужно создать собственный класс, массив (или коллекцию) объектов
которого необходимо отсортировать.

Для сравнения подходов полезно изучить готовую реализацию сортировки из
стандартной библиотеки выбранного языка: `std::sort`/`std::stable_sort` — в
C++, `Collections.sort`/`Arrays.sort` и интерфейс `Comparable`/`Comparator` —
в Java, `Array.Sort`/`List<T>.Sort` и интерфейс `IComparable`/`IComparer` —
в C#, встроенные `sorted()`/`list.sort()` с параметром `key` — в Python.

### Варианты заданий

1. Bubble sort. Patience sorting.
2. Cocktail sort. Strand sort.
3. Comb sort. Tournament sort.
4. Gnome sort. Pigeonhole sort.
5. Selection sort. Bucket sort.
6. Insertion sort. Counting sort.
7. Shell sort. LSD Radix sort.
8. Binary tree sort. MSD Radix sort.
9. Library sort. Spreadsort.
10. Merge sort. Bozo sort.
11. In-place merge sort. Bogosort.
12. Heapsort. Stooge sort.
13. Smoothsort. Simple pancake sort.
14. Quicksort. Sorting networks.

## Задание 2. Графы

Реализовать обобщённый контейнер (в C++ — шаблон класса) в соответствии с
выбранным вариантом. Реализованный контейнер должен соответствовать
следующим требованиям:

- иметь как минимум один параметр обобщённого типа, задающий тип элементов,
  для хранения которых используется контейнер;
- предоставлять публичные псевдонимы/описания используемых типов там, где
  это принято в выбранном языке (`typedef`/`using` — в C++; параметры типов
  и вложенные типы — в Java и C#; аннотации типов — в Python); полный
  перечень определяется вариантом задания и разработчиком;
- конструктор по умолчанию, создающий пустой контейнер;
- конструктор копирования (в языках без явного конструктора копирования —
  метод глубокого копирования, например `Clone`/`copy`/аналогичный
  статический фабричный метод);
- деструктор, если это предусмотрено языком и необходимо для освобождения
  ресурсов (либо эквивалентный механизм: `Dispose`/`using`,
  `try-with-resources`, `__del__` — если требуется явное освобождение
  ресурсов помимо сборки мусора);
- проверку на пустой контейнер (метод `empty`/`is_empty`);
- очистку контейнера (метод `clear`);
- операцию присваивания копированием: перегруженный оператор `=` — в C++;
  в языках, где такая перегрузка невозможна (Java, C#, Python), —
  именованный метод копирования состояния (`assignFrom`/`CopyFrom`);
- операции сравнения: `==`, `!=`, `>`, `<`, `>=`, `<=` (в виде операторов —
  в C++ и C#; через `equals`/`Comparable` — в Java; через магические методы
  `__eq__`, `__lt__` и т. д. — в Python);
- методы для доступа к элементам контейнера (перечень зависит от варианта
  задания);
- методы для добавления элементов в контейнер (перечень зависит от варианта
  задания);
- методы для удаления элементов из контейнера (перечень зависит от варианта
  задания);
- классы (или объекты) итераторов для перебора элементов и методы для их
  создания (тип итераторов и перечень методов зависит от варианта задания);
  используйте идиоматичный для языка механизм итерации — пользовательские
  итераторы, удовлетворяющие концепции итератора STL, — в C++; интерфейсы
  `Iterator`/`Iterable` — в Java; `IEnumerator`/`IEnumerable` и `yield` — в
  C#; протокол `__iter__`/`__next__` — в Python;
- текстовое представление контейнера, построенное с помощью его итераторов
  и обобщённого алгоритма обхода (`operator<<` со `std::for_each` — в C++;
  переопределённый `toString()`/`ToString()`/`__str__`, использующий
  итерацию по контейнеру, — в Java, C#, Python);
- выброс исключения при возникновении ошибочной ситуации.

Механизм тестирования — на усмотрение разработчика: консольное меню или
unit-тесты.

При защите лабораторной работы студент должен уметь работать с обобщёнными
типами выбранного языка, знать структуру и свойства стандартной библиотеки
контейнеров этого языка, типы итераторов и способы использования
обобщённых алгоритмов и функциональных объектов (функторов/лямбда-выражений
/делегатов).
