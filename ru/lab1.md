# Лабораторная работа №1. Основы ООП: разработка класса

## Задание

Реализовать один из вариантов, перечисленных ниже, на одном из разрешённых
языков программирования (см. `common_requirements.md`). Для класса нужно
подготовить документацию, сгенерированную штатным генератором документации
для выбранного языка (Doxygen — для C++, Javadoc — для Java, XML-документация
и DocFX — для C#, Sphinx/pdoc — для Python).

Для проверки класса нужно реализовать консольную программу с меню. При запуске unit-тестов необходимо покрыть более
**90%**, используя подходящую библиотеку модульного
тестирования для выбранного языка (например, UnitTest++/Catch2/GoogleTest —
для C++, JUnit — для Java, NUnit/xUnit — для C#, pytest/unittest — для
Python).

Каждый реализованный класс должен обладать следующими свойствами независимо
от языка реализации:

- инкапсуляция;
- отделение консольного пользовательского интерфейса программы от реализации
  класса;
- конструктор копирования и операция присваивания копированием, если это
  уместно для класса;
- корректное освобождение ресурсов (деструктор, `Dispose`/`using`,
  `try-with-resources`, менеджер контекста и т. п. — в зависимости от того,
  что предусмотрено языком), если это необходимо;
- операции сравнения на равенство (`==`, `!=`);
- операции для чтения объекта из текста/потока и записи его в текст/поток;
- взаимная независимость класса и пользовательского интерфейса, который его
  использует;
- отделение объявления (интерфейса) класса от его реализации, насколько это
  предусмотрено средствами языка.

## Перенос требований, специфичных для C++

Формулировки вариантов исторически ориентированы на C++ (перегрузка
операторов, разделение `.h`/`.cpp`). При выполнении задания на другом языке
нужно реализовать ту же семантику доступными средствами языка. Ниже —
таблица соответствий.

| Требование | C++ | Java | C# | Python |
|---|---|---|---|---|
| Разделение объявления и реализации | заголовочный файл (`.h`) и файл реализации (`.cpp`) | интерфейс + отдельный класс реализации | `partial class`, либо интерфейс + класс реализации | абстрактный базовый класс (`abc.ABC`) + класс реализации, отдельные модули |
| Сравнение на равенство | `operator==`, `operator!=` | переопределение `equals()` и `hashCode()` | переопределение `Equals()` и `GetHashCode()`, при желании — операторов `==`/`!=` | магические методы `__eq__`, `__hash__` |
| Вывод/чтение объекта | `operator<<`, `operator>>` | `toString()` + статический метод `parse(String)` | переопределение `ToString()` + статический метод `Parse`/`TryParse` | `__str__`/`__repr__` + метод `from_string` (`@classmethod`) |
| Арифметические операции (`+`, `-`, `*`, `/` и их составные формы) | перегрузка соответствующих операторов | именованные методы (`add`, `subtract`, `multiply`, `divide`), так как Java не поддерживает перегрузку операторов | перегрузка операторов (`public static T operator +(...)`) | магические методы (`__add__`, `__sub__`, `__mul__`, `__truediv__`, `__iadd__`, …) |
| Индексация (`[]`) | `operator[]` | именованные методы (`get(i)` / `set(i, v)`) | индексатор `this[int i] { get; set; }` | `__getitem__` / `__setitem__` |
| Пре-/постинкремент и декремент (`++`, `--`) | `operator++`, `operator--` | именованные методы `increment()` / `decrement()` (в Java нет перегрузки операторов) | перегрузка `operator ++` / `operator --` | методы `increment()` / `decrement()` (в Python нет постфиксных операторов) |
| Приведение к другому типу (например, к `double`) | пользовательский оператор приведения | метод `doubleValue()` | пользовательский оператор преобразования (`explicit operator double`) | метод `__float__` |
| Операции сравнения порядка (`>`, `>=`, `<`, `<=`) | перегрузка операторов сравнения | реализация `Comparable<T>` (`compareTo`) | реализация `IComparable<T>` либо перегрузка операторов | магические методы `__lt__`, `__le__`, `__gt__`, `__ge__` |

Если в выбранном языке нет языкового средства для конкретного пункта —
реализуйте эквивалентную по смыслу функциональность именованным методом,
сохранив инкапсуляцию и тестируемость. В формулировках вариантов ниже слово
«оператор» следует читать как «операция (оператор языка или именованный
метод — см. таблицу соответствий)».

## 1.1 Вектор

Описать класс для работы с вектором, заданным координатами концов в
трёхмерном пространстве. Класс должен реализовывать следующие возможности:

- получение координат концов вектора;
- вычисление длины вектора;
- сложение двух векторов (`+`, `+=`);
- вычитание двух векторов (`-`, `-=`);
- векторное произведение двух векторов (`*`, `*=`);
- произведение вектора на число (`*`, `*=`);
- деление вектора на число (`/`, `/=`);
- вычисление косинуса угла между двумя векторами;
- операции сравнения двух векторов по длине (`>`, `>=`, `<`, `<=`).

## 1.2 Англо-русский словарь

Описать класс, реализующий англо-русский словарь на основе двоичного дерева
поиска (в узле хранится пара слов, английское слово — ключ). Класс должен
реализовывать следующие возможности:

- добавление нового английского слова и перевода для него (`+=`); в C++
  предусмотреть перегрузку как для C-строк (`char*`), так и для `std::string`;
- удаление существующего английского слова из словаря (`-=`);
- поиск перевода английского слова (`[]`);
- замену перевода английского слова (`[]`);
- определение количества слов в словаре;
- загрузку словаря из файла.

## 1.3 Прямоугольник

Описать класс прямоугольника со сторонами, параллельными осям координат.
Координаты вершин должны быть целочисленными. Класс должен реализовывать
следующие возможности:

- получение координат вершин;
- перемещение прямоугольника;
- изменение размера;
- увеличение размера на единицу по каждой из осей (пре- и постинкремент);
- уменьшение размера на единицу по каждой из осей (пре- и постдекремент);
- построение наименьшего прямоугольника, содержащего два заданных
  прямоугольника (`+`, `+=`);
- построение прямоугольника, являющегося пересечением двух прямоугольников
  (`-`, `-=`).

## 1.4 Теория множеств

Описать класс «Множество». Класс должен реализовывать следующие возможности:

- элементом множества может быть другое множество;
- проверка на пустое множество;
- добавление элемента;
- удаление элемента;
- определение мощности множества;
- проверка принадлежности элемента множеству (`[]`);
- объединение двух множеств (`+`, `+=`);
- пересечение двух множеств (`*`, `*=`);
- разность двух множеств (`-`, `-=`);
- построение булеана (множества всех подмножеств) данного множества.

## 1.6 Математика

### 1.6.1 Натуральная дробь со знаком

Описать класс, реализующий тип данных «Натуральная дробь со знаком». Дробь
должна всегда храниться в сокращённом виде. Класс должен реализовывать
следующие возможности:

- получение числителя, знаменателя и целой части;
- сложение двух дробей (`+`, `+=`);
- сложение дроби с целым числом (`+`, `+=`);
- вычитание двух дробей (`-`, `-=`);
- вычитание целого числа из дроби (`-`, `-=`);
- произведение двух дробей (`*`, `*=`);
- произведение дроби на целое число (`*`, `*=`);
- деление двух дробей (`/`, `/=`);
- деление дроби на целое число (`/`, `/=`);
- пре- и постинкремент, пре- и постдекремент;
- сравнение двух дробей и дроби с целым числом (`>`, `>=`, `<`, `<=`);
- приведение к типу с плавающей точкой (`double`).

### 1.6.2 Многочлен от одной переменной

Описать класс многочлена от одной переменной, задаваемого степенью и
массивом коэффициентов. Класс должен реализовывать следующие возможности:

- получение значений коэффициентов (`[]`);
- вычисление значения многочлена для заданного аргумента (операция вызова

- вычитание двух многочленов (`-`, `-=`);
- произведение двух многочленов (`*`, `*=`);
- деление двух многочленов (`/`, `/=`).

### 1.6.3 Длинное целое со знаком

Описать класс, реализующий тип данных «длинное целое со знаком»
неограниченной длины, и операции над ним. Класс должен реализовывать

- сложение длинного целого с обычным целым (`+`, `+=`);

## 1.8 Абстрактные машины

Описать классы, реализующие абстрактную машину, её ленту, программу и
правила, каретку, алфавит, строку. Набор классов зависит от вида
абстрактной машины: количество классов может варьироваться, но не должно
быть меньше трёх. Классы должны реализовывать следующие возможности:

- загрузку программы из потока ввода;
- загрузку состояния ленты из потока;
- добавление, удаление и просмотр правил;
- задание и изменение значений на ленте;

файлу, содержащему начальное состояние абстрактной машины и программу для
интерпретации. После запуска программа считывает содержимое файла и
выполняет интерпретацию правил. Если в командной строке указан флаг `-log`,
после выполнения каждого правила в консоль должна выводиться информация о
текущем состоянии абстрактной машины.
